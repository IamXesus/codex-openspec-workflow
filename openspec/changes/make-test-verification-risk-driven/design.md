## Context

The package distributes declarative agent behavior through skills, schema instructions, task templates, and a managed policy. The current v3 trace marker correctly requires concrete verification for every implementation task, but its authoring guidance does not distinguish a shared evidence set from a newly created test. The deterministic validator can prove trace completeness and placeholder absence; it cannot prove semantic test value.

The accepted correction must affect future work immediately after package installation, permit bounded consolidation in the touched feature area, and avoid a repository-wide test rewrite or another mandatory planning artifact.

## Goals / Non-Goals

Goals:

- Make minimum-sufficient, risk-driven verification the canonical shared authoring behavior.
- Prefer existing evidence and one stable primary acceptance path before supplementary tests.
- Preserve focused lower-level checks for risks that a vertical slice cannot prove economically.
- Make final review examine test-delta value and overlap.
- Keep ordinary feature work bounded to touched-area consolidation.

Non-goals:

- No automatic deletion or modification of consumer tests.
- No repository-wide PayFlow consolidation in this change.
- No new trace syntax, validator parser, validation document, test quota, coverage threshold, or mandatory mutation tool.
- No requirement that every change use browser E2E or that every scenario receive a separate test.

## Decisions

The accepted decisions are recorded once in `proposal.md` as DEC-001 through DEC-004.

Implementation will keep the existing `verification=` field. Shared evidence is expressed in ordinary concrete text, for example by naming one existing or focused check that several traced tasks reuse. This retains validator compatibility and avoids converting verification economy into metadata overhead.

The contract will distinguish primary acceptance evidence from supplementary risk evidence. A vertical slice is preferred only when it is stable and faithfully crosses the relevant internal boundaries. Provider-specific persistence, concurrency, transactions, money invariants, authorization negatives, retries, and external contracts remain eligible for narrower checks at their faithful layer.

The package version will advance from `1.2.1` to `1.3.0` because installed receipts must expose the new shared workflow behavior. No tag, release, installation, or publication is part of this change.

## Component Ownership

**Architecture impact:** none

- `skills/openspec-workflow/SKILL.md` owns the cross-phase verification selection and ordinary-development ratchet.
- `openspec/schemas/evidence-core/schema.yaml` and `openspec/schemas/evidence-heavy/schema.yaml` own task-authoring instructions generated by OpenSpec.
- Their existing `templates/tasks.md` files prime the concise minimum-sufficient trace wording.
- `skills/coding-guardrails/SKILL.md` owns direct implementation behavior outside and inside OpenSpec.
- `skills/code-reviewer/SKILL.md` owns semantic test-delta review.
- Existing package/policy tests own distribution consistency; no new test framework or validator responsibility is introduced.

## Risks / Mitigations

- **Risk:** Agents interpret vertical-slice preference as E2E-only policy. **Mitigation:** Name the distinct risks that require unit, real-provider integration, contract, browser, or runtime checks and require the cheapest faithful layer.
- **Risk:** Touched-area consolidation expands into unrelated cleanup. **Mitigation:** State that replacement evidence and current feature scope are prerequisites; repository-wide consolidation requires a separate explicit request.
- **Risk:** Review language becomes a new bookkeeping burden. **Mitigation:** Reuse the existing final review and require a compact semantic judgment, not a new table or artifact.
- **Risk:** Text-only regressions become brittle copies of prose. **Mitigation:** Extend the existing shared-contract test with a small set of stable concepts and verify both schemas/templates share the rule; do not mirror every sentence.
- **Risk:** Package metadata remains inconsistent. **Mitigation:** Keep one explicit release-version assertion and use existing lock/README consistency checks without duplicating the version literal across unrelated tests.
